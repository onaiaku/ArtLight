# ArtLight 1.6.0 - 2026-11-06

Developed by onaiaku & Rias.

## Fixed

- **HDR streams no longer fight the graphics card for every frame.** On Linux, a captured HDR frame reached the encoder by way of a full copy through system memory — 4K and 1440p at high refresh rates could not be copied that fast, so the picture stuttered and tore no matter how good the connection was. Captured frames now go straight onto the GPU as textures, which is where the encoder was always going to read them from. Both screens, both codecs, no copy.
- **The second screen keeps its own resolution when it is not the same as the main one.** The composed desktop is now built against the geometry the connector actually has rather than the mode that was requested, so a 1440p monitor alongside a 4K stream comes up at its own size instead of being refused.
- **Stopping a stream stops the monitor's stream with it.** Ending an app left the second screen running with no window on it; the monitor's session and the display it owned are now stopped and released together with the game.
- **A second screen held for resume can no longer outlive the app that asked for it.** Resuming still works; a monitor left behind after the app has gone does not.
- **Rejoining a second screen after an exit no longer answers 503.** Retained monitor leases are verified against the client that owns them, and a fresh lease is applied instead of being refused.
- **A streamed display goes back where you left it.** Each streamed display remembers its own position instead of sharing one, so the second screen no longer lands back on top of the first.
- **Holding the second screen no longer empties the app list.** Resume and Disconnect stay at the top and the rest of the library stays visible underneath, with the running app still marked as streaming.
- **The second screen honours the HDR request the client sends.** It used to be created with HDR hard-coded off, so a client asking for HDR still got a flat, washed-out picture on the second panel.

## Added

- **RTX HDR on Linux, for SDR content, off by default.** When a client asks for HDR and the thing being streamed is SDR — a desktop, a game with HDR off — the host can synthesise an HDR10 image on the GPU before it reaches the encoder, with peak-brightness metadata, for both NVENC and PyroWave. It is a conversion, not a claim of real HDR: it stays off unless you turn it on for an app in the Web UI, and if the source is already HDR, or the GPU cannot convert, the host refuses the stream and says why instead of relabelling it.
- **The RTX HDR controls are visible on Linux hosts.** The conversion shipped in the encoder but had no switch a Linux user could reach.
- **Capture diagnostics name the output they are capturing.** The log says which connector a session is reading, and what the compositor said about the mode that was asked for, so a bad stream can be diagnosed from the log instead of by guesswork.

## Notes

- RTX HDR is not a replacement for HDR content. A game rendering in HDR, or a film mastered in HDR, is passed through untouched and looks better than anything converted. RTX HDR exists for the case where there is no HDR to pass through.
- Windows Defender may flag the download as unsafe; Windows does not know what ArtLight is yet.
- Code signing via SignPath Foundation is being set up. Until the first signed build, verify downloads by building from source or checking CI artifacts against this repository.
